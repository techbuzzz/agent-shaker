## 1. Ядро гипотезы

> **ЕСЛИ** российская инженерная команда ведёт работу нескольких ИИ-агентов параллельно и
> дефицитный ресурс в этой работе — человеческое внимание, а не токены, **ТО** self-hosted слой,
> который даёт агентам общий источник истины, встроенный ритуал (стендап, milestone) и
> проверяемый журнал действий по каждому агенту, **БУДЕТ** востребован как замена ручного
> учёта и вебхуков, **ПОТОМУ ЧТО** (а) практика параллельной агентной работы стала нормой
> (95% dev'ов используют ИИ-инструменты еженедельно, 55% работают с агентами регулярно),
> (б) форма требований к доказуемости уже кодифицирована (проект стандарта ОСП, 3-МР ЦБ
> от 16.06.2026), (в) в РФ нет публичного продукта, закрывающего именно эту задачу, и
> (г) модель денег в российском open source — платная поддержка, SLA и хостинг, а не лицензия.

**Ключевая структурная особенность:** гипотеза составная. У неё есть **проверяемая часть** (проблема координации существует и рынок есть) и **непроверяемая на сегодня часть** (слой доказательств как дифференциатор не построен, а готовность платить не измерена). Ниже они разделены явно — потому что смешивать их в одном «тесте идеи» значит получить зелёный статус за счёт решенной задачи.

## 3. Несущие допущения

Идея держится на девяти допущениях; они связаны с H1–H12.

| Допущение | На чём держится | Если опровергнуто |
|---|---|---|
| A1. Параллельная агентная работа — норма | H1 | Нет рынка, нет продукта |
| A2. Дефицит — внимание, а не токены | H2 | Слой координации теряет главный аргумент ценности |
| A3. Ниша «доказательств» в РФ не занята | H7 | Позиция не выделяется, конкуренция в лоб |
| A4. Форма требований известна заранее | H9 | Продукт строится под мишень, которая разъедется |
| A5. Команды готовы платить | H8, H11 | Позиция остаётся профессиональной репутацией без дохода |
| A6. Отсутствие конкурента = спрос | H7, H8 | Подтверждается только интервью |
| A7. Ниша, где не нужен сертификат/юрлицо | Доменный контекст, O1–O4 | Ниша недоступна целиком |
| A8. Деньги в RU open source — поддержка и хостинг | Отраслевая практика | Модель выручки не работает |
| A9. Вендоры не закроют нишу раньше | H1–H9 | Гонка проиграна до финиша; единственный шанс — гибридная схема (53–57%) |

**Заметка о A9.** Допущение опровергнуто частично уже сейчас: Microsoft Agent 365, Foundry Agent Service, Vertex AI Agent Builder, Claude Managed Agents, OpenAI Agents API закрывают категорию сверху. Оно заменено на более узкое: «вендоры не успеют закрыть нишу требованиями трассируемости раньше, чем она будет закреплена в стандарте». Проверяемость этого — H8.

## 4. Критерии смерти гипотезы

Гипотеза считается опровергнутой, если выполнено **любое** из:

| # | Критерий | Как обнаружить |
|---|---|---|
| K1 | H8: 10 интервью дают 0 подтверждений бюджета/запроса на трассируемость действий ИИ-агентов | Интервью |
| K2 | H11: 3 месяца платного оффера без единого платящего клиента | Платный оффер |
| K3 | H3+H4: на 2–3 пилотах координационная боль оказывается ниже порога и/или продукт не даёт измеримого выигрыша | Пилот 4 недели |
| K4 | H10: за 60 дней 0 установок с 2+ активными агентами при активном дистрибуционном канале (реестр MCP + статья + techbuzzz.ru) | Телеметрия установок |
| K5 | H7: вендор (Microsoft/Anthropic/Google) выпускает продукт с журналом + мандатами в РФ-доступной редакции раньше, чем закрыты M3+M4 | Мониторинг категории |
| K6 | H9: проект стандарта и 3-МР расходятся в существенных требованиях к журналу/мандату | Повторная сверка |

**Обратное (подтверждение) условие для перехода к позиционированию «слой доказательств»:** закрыты M3 **и** M4, и H8 даёт ≥ 3 из 10 подтверждений.

## 5. Границы проверки

**Вне гипотезы (не проверяем здесь):**

- Исполнение агентов — сознательно вне объёма продукта.
- Multi-tenancy, биллинг, Git-слой с вебхуками.
- Конкуренция с рантаймами и execution-фреймворками (LangGraph, Microsoft Agent Framework) — другой слой.
- Реестр отечественного ПО, сертификация ФСТЭК, господдержка — закрыты для соло-мейнтейнера по определению, см. доменный контекст O1–O4.

**Вне гипотезы, но обязательно к синхронизации:** если команда вносит изменения в продукт, статус H5, H13, H14 пересматривается — карточка не должна расходиться с кодом.

## 7. Открытые вопросы автору

Не заполнены — требуют решения владельца продукта, а не догадки.

1. **Юридическое лицо.** Есть ли ИП/ООО с УКЭП? Влияет не на позиционирование, а на горизонт 6–12 месяцев: Сколово, постановление № 550, часть путей к деньгам доступны только юрлицам. *(Требуется подтверждение автора.)*
2. **Бюджет.** Есть ли любые деньги на инфраструктуру (хостинг демо-инстанса, домен, SLA)? От этого зависит, можно ли открыть публичный demo-инстанс — без него реестр MCP недоступен.
3. **Горизонт.** Сколько часов в неделю автор готов вкладывать в проект на горизонте 3 месяцев? Это переводит «недели» из ROADMAP в календарные даты.
4. **Риск слова «аудит».** Готов ли автор до закрытия M3+M4 не произносить его ни в одном канале? Это цена позиции B, и она прямо названа в рыночном анализе.
5. **Готовность к интервью.** Кто из 10–15 респондентов доступен через контур SEFE и профессиональные контакты? Без этого H8 не проверяется, а H8 — главная неизвестная.
6. **Формат интервью.** Кто проводит: автор или отдельный интервьюер? Свои ли клиенты дают смещённые ответы («своё всегда хорошо»).
